# Как запустить и представить PneumoGuard AI

Это учебное исследование на открытых изображениях. Оно не ставит диагноз и не предназначено для принятия медицинских решений. Не загружайте снимки пациентов или личные данные.

## Что находится в проекте

- `notebooks/PneumoGuard_AI.ipynb` — главная тетрадь с объяснениями и выполняемым кодом. Она сама устанавливает нужные библиотеки, загружает открытый набор изображений, обучает модель и считает результаты.
- `results/report.md` — отчёт с настоящими результатами после полного запуска. До его появления нельзя называть проценты качества.
- `docs/demo_script.md` — текст двухминутного выступления на английском.
- `docs/one_page_writeup.md` — краткое описание проекта для судей.
- `docs/submission_checklist.md` — список проверок перед отправкой.

Главная идея: обычная модель обязана выбрать один из двух классов. Наша дополнительная проверка позволяет ей отказаться от ответа на неуверенном примере. Мы измеряем, уменьшаются ли ошибки и сколько изображений тогда нужно проверить вручную.

## 1. Открыть тетрадь в Google Colab

1. Сохраните папку проекта на компьютер и распакуйте архив, если получили ZIP.
2. Откройте [Google Colab](https://colab.research.google.com/) и войдите в свой аккаунт Google.
3. Выберите **File → Upload notebook** («Файл → Загрузить блокнот»). Если открылось окно выбора тетради, нажмите вкладку **Upload** («Загрузить»).
4. Нажмите **Browse** («Обзор») и выберите `notebooks/PneumoGuard_AI.ipynb` в распакованной папке.
5. Должна открыться тетрадь с заголовком PneumoGuard AI. Сохраните свою копию через **File → Save a copy in Drive**, чтобы не потерять работу.

Не нужно отдельно загружать папку `src`: код, необходимый для запуска, включён в тетрадь. Не нужно покупать доступ к платному сервису или включать графический ускоритель: предусмотрена работа на обычном процессоре.

## 2. Запустить исследование

1. Прочитайте предупреждение и первые пояснения в тетради.
2. Для основных результатов используйте полный режим. Оставьте в первой ячейке настроек `SMOKE_TEST = False`. Значение `True` включает **smoke test** — быструю проверку работы, которая не заменяет итоговый эксперимент.
3. Нажмите **Runtime → Run all** («Среда выполнения → Выполнить всё»). Если Colab просит разрешить запуск загруженной тетради, подтвердите его после просмотра кода и источника файла.
4. Дождитесь завершения. Во время обучения будут появляться строки с номером этапа обучения и качеством на проверочной части данных. Не меняйте настройки по итогам тестовых результатов ради более красивых чисел.
5. В конце должны появиться таблицы сравнения, матрицы ошибок, график доли автоматических ответов и ошибок, а также реальные примеры предсказаний.
6. В интерактивной части выберите номер открытого тестового изображения и выполните предсказание. Сравните ответ модели, решение «ответить или передать на проверку» и исходную метку набора.

Если выполнение остановилось с красной ошибкой, сохраните её текст и номер ячейки. Не заменяйте результат придуманным процентом. После перезапуска среды требуется снова выполнить тетрадь с начала.

## 3. Сохранить результаты

В левой панели Colab нажмите значок папки **Files** («Файлы»). Найдите созданные папки с результатами и сохранёнными весами модели. Откройте меню **⋮** рядом с нужным файлом и выберите **Download** («Скачать»). Если тетрадь предлагает скачать готовый архив результатов, используйте его.

Сохраните всю папку `results`: отчёт `report.md`, таблицы `comparison.csv`, `test_predictions.csv`, `failure_examples.csv`, параметры `policy.json`, сведения о данных `split_manifest.json`, файлы `metrics.json`, `environment.json`, `training_history.csv`, обученные веса `best_model.pt` и графики в `figures`. Удобнее воспользоваться кнопкой скачивания ZIP в конце тетради. Не добавляйте сам набор изображений в GitHub. Также выберите **File → Download → Download .ipynb**, чтобы сохранить выполненную тетрадь вместе с видимыми результатами. Файлы внутри Colab могут исчезнуть после завершения сеанса.

Прочитайте `results/report.md`. В `docs/demo_script.md` замените подсказки в квадратных скобках только на числа из этого отчёта. Для объяснения ошибки выберите настоящий пример, который показывает тетрадь. Не придумывайте медицинскую причину ошибки по маленькому изображению.

## 4. Разместить свою копию в GitHub — вручную

Этот проект автоматически никуда не публикуется и не отправляется. Следующие действия выполните только когда будете готовы сделать материалы общедоступными.

1. Откройте [GitHub](https://github.com/), войдите в свой аккаунт и нажмите **+ → New repository**.
2. Укажите название `pneumoguard-ai-2026`, выберите **Public** и нажмите **Create repository**. Не загружайте личные данные.
3. На странице нового репозитория нажмите **uploading an existing file**. Для уже созданного репозитория используйте **Add file → Upload files**.
4. Перетащите содержимое папки проекта, сохранив папки `notebooks`, `docs`, `src` и `tests`, если они есть. Добавьте измеренные результаты полного запуска. Не перетаскивайте `.git`, кэш, скачанный набор данных или временные файлы.
5. Нажмите **Commit changes**. Это сохраняет файлы в выбранном репозитории.
6. Откройте страницу репозитория в приватном окне браузера. Проверьте, что судья без вашего аккаунта видит README, тетрадь и отчёт.
7. В [Colab](https://colab.research.google.com/) выберите **File → Open notebook → GitHub**, вставьте ссылку своего репозитория и откройте тетрадь. Проверьте запуск чистой копии до подачи.

Если у вас уже есть подходящий репозиторий, можно загрузить файлы в него через **Add file → Upload files**, предварительно сохранив старую версию нужных материалов.

## 5. Что объяснить судьям

«Мы обучили небольшую нейросеть на открытых детских рентгеновских изображениях низкого разрешения. Мы сравниваем её с простым правилом: всегда выбирать самый частый класс. Два порога выбираются только на проверочной части данных: мы ищем наибольшую долю автоматических ответов при наблюдаемой доле ошибок среди них не выше 5%. Это настройка эксперимента, а не обещание безопасности. Затем на отдельной тестовой части мы измеряем ошибки и долю изображений, которые модель передаёт человеку».

Ложноотрицательная ошибка: в наборе стоит метка Pneumonia, а автоматический ответ модели — Normal. Ложноположительная: в наборе стоит Normal, а модель автоматически выбирает Pneumonia. Отказ от ответа учитывается отдельно как дополнительная работа человека.

Сравнивая проценты, обязательно называйте долю изображений, на которые модель ответила. Меньше ошибок среди выбранных изображений не означает, что система безопасна для пациентов. Если метод не улучшил результат, это тоже честный исследовательский вывод.

В материалах уже предусмотрено указание помощи ChatGPT и OpenAI Codex. Проверьте актуальные правила конкурса об использовании ИИ, сроках и составе заявки. Не утверждайте, что проект имеет клиническое подтверждение, партнёров или награды.

Обязательная фраза для английских материалов: “This project is a prototype and is not medical advice.”
